## Added 2026-10-22

- The arranging step is now `arrange-plugin-eval-results.py` (`<keep-temp>` is the directory of `claude-eval-<id>` homes, or the one home a run's `tracePath` names); the spec's § Behavior › Eval harness should say so.
- An Agent result without `totalTokens` / `totalToolUseCount` is drift only when its `status` is `completed` (`async_launched` carries none).
- `cat -n f` / `cat -b f` / `cat -s f` count as shell reads (per-command option grammar); the 2026-10-21 baseline's shell figures were undercounted and are revised in the report.
- The gate's `shunt.jsonl` record shape (`decision`, `tool`, `input`, the literal `deny`) is known only to the grader's hook columns, and `arrange` never places the log beside a transcript; specs/read-shunt.md names the hook's log at `tasks/.shunt/<session>.jsonl`. Add a D7 note: when the hook is built, the parser owns a `ShuntDecision` reader/writer beside `SHUNT_LOG` and `arrange` copies the log (quality-gate finding, advisory, 2026-10-22; resolved 2026-10-23 in 31b1863 — `ShuntDecision`, `read_shunt_log`, `find_shunt_log` in the parser, `arrange` copies the log; D7 names the reader).
- `ToolResult` keeps the whole `toolUseResult` (a Read's full file content) until the classify pass at the end of `parse_transcript`, so one session's memory scales with its read volume rather than its line count, and the Read-only `numbered` / `non_file` fields sit on the generic result record. The module docstring's "only metadata is kept" overstates it. Upgrade path: classify each tool use at result time (uses precede results) and keep only `(bytes, sidechain)` on the result; the parent call order then follows append order. Left for a later change — the 301-session baseline ran within minutes, and a per-session transcript is dropped after parsing (quality-gate finding, SHOULD-FIX manual, 2026-10-22; resolved 2026-10-23 in 31b1863 and 6d2bed9 — a use is classified when its result arrives, `ToolResult` keeps size and error, a result logged before its use is held in `_pending`; the real root gives the same 304 rows before and after).
- `Transcript` answers two frames of reference with look-alike predicates: `ToolUse.sidechain` is session-relative (a sub-agent's call) while the `own_*` accessors are file-relative (this file's context), so on a `subagents/` file `own_reads()` and `sidechain_reads()` return the same list and on a parent file they partition `reads()`; a caller summing across files must know `is_subagent`. Upgrade path: rename the session-relative accessors (`subagent_reads()`), or let `SessionReads` be the only object that answers session-frame questions. Left as is — `SessionReads.session_sidechain_reads` already carries the cross-file union both CLIs use (quality-gate finding, SHOULD-FIX advisory, 2026-10-22; resolved 2026-10-23 in 31b1863 and 6d2bed9 — `subagent_reads()` / `counted_subagent_reads()` on `Transcript`, `SessionReads.counted_subagent_reads`, the two frames named above `own_tool_uses`).
- Real roots repeat a tool use: `api-request-blob` records copy the request's `tool_use` blocks (no uuid, no isSidechain) and a resumed session re-logs assistant records verbatim; the parser reads only `assistant` / `user` / `system` records and absorbs a tool-use id — and its result — once, first record wins. The spec's § Edge Cases should name the two shapes (found 2026-10-22; baseline revised).
- The grader's `subagent_tokens` uses `None` for two facts — no sub-agent dispatched (a true zero) and a sub-agent whose result carried no counters (unknown) — while `subagent_tool_uses` falls back to the sub-agent transcripts, so `paired_means` skips `None` tokens and averages zero tool uses over different denominators; a control arm that never delegates shows `-`, and Mode C's "total cost not worse than control" cannot be read off the means. Upgrade path: tokens are 0 when `parent.agent_calls()` is empty, `None` only for a dispatched Agent with no counters and no transcript; the fixture rows pinning `-` move to `0` (quality-gate finding, SHOULD-FIX manual, 2026-10-22; resolved 2026-10-23 in 31b1863 and 6d2bed9 — `SessionReads.subagent_totals()` sums per Agent call: counters, else the transcript its `agentId` names, else unknown; `(0, 0)` with no call; the token unit is stated in the grader docstring).
- `fixture_gen.broken_bounds` recovers the comparison side and the quantity by parsing each `Promise` field's name (`min_`/`max_` + quantity) and indexing a dict `measure` must spell the same way — three places bound by a naming convention. Upgrade path: a `Bound(min, max)` per quantity on `Promise` and `measure` returning a dict keyed by the field names (quality-gate finding, SHOULD-FIX manual, 2026-10-22; resolved 2026-10-23 in 31b1863 and 6d2bed9 — `Bound(min, max)` per quantity, `broken_side` returns the side and bound, `broken_bounds` owns the sentence).
- `LARGE_BYTES` is D3's per-read threshold but `large()` bounds `min_total_bytes`, the workspace sum, so a many-small-files case (`load-record-callers`, 40 files ≤ 80 lines) keeps its "large" promise while no single file crosses the threshold the parser measures — only shell routing-around can register on it. Decide whether AC8's "over 32 KB" means the workspace (then rename the promise `min_workspace_bytes`) or a file (then bound large cases by `min_longest_bytes`) (quality-gate finding, NITPICK advisory, owner human, 2026-10-22).
