¶ Summary

Before any read gate ships, the repository measures how often the parent agent pulls whole files over the shunt threshold into its own context, from the session transcripts already on disk, and builds the eval harness that will judge a gate when one is built. Both tools read the same transcript format through one parser. The work supersedes PR #128, whose two gate implementations and paired eval are kept as evidence. The research, the gate design and the eval design this spec implements are specs/read-shunt.md; this spec covers its Tier 0 and its grader, fixtures and rubric, on Claude Code only.

Behavior

Incidence report

read-incidence.py walks a transcript root (default ~/.claude/projects) and reads every main-loop session transcript, streaming one JSON line at a time so an 800 MB root finishes in minutes and nothing but metadata is held in memory. Sub-agent transcripts under each session's subagents/ directory are read too and reported in their own column, never mixed with the parent's.

For every Read tool use it records the input (file_path, offset, limit) and the result metadata (totalLines, numLines, startLine, content length in bytes). A read with neither offset nor limit is a whole-file read; one whose numLines is below totalLines without a limit is a whole-file read the tool truncated at its own cap, counted as whole-file and flagged. A read is large when its content is at least --bytes (default 32768) or its totalLines is at least --lines (default 800). A result that is not a text file (image, PDF, notebook, directory, error) is excluded from every count and tallied once as excluded.

For every Bash tool use whose command is a bare shell read of one or more paths (cat, head, tail, less, more, sed -n with a print range), neither piped nor redirected, it records the result length as bytes delivered. Piped and redirected forms (cat f | grep, cat f > g) are not counted; every file in a chained command (cat a; cat b) is.

The report, as a Markdown table on stdout or JSON with --json, gives per session and in aggregate: reads, whole-file large reads, bytes those reads delivered, their share of all tool-result bytes in the parent loop, shell reads and their bytes, the largest single result, re-reads of a path already read in the same session, the parent's final context size (input, cache-creation and cache-read tokens of its last assistant message), compaction markers when the transcript carries them, and sub-agent reads beside the parent's. File paths appear as basenames unless --paths is passed; file contents never appear.

Go rule

The baseline run is committed as tasks/eval-results/read-shunt/baseline-<date>.md with the aggregate table and the rule applied: the gate (Tier 1 and Tier 2 of specs/read-shunt.md) is built only when whole-file large reads account for at least 10% of the parent's tool-result bytes in the median session, or at least 25% in a quarter of sessions. Below that, the report records "not worth gating" and the brief's remaining tiers stay unbuilt.

Eval harness

evals/read-shunt/ is a claude plugin eval suite under the plugin root: eleven cases, each a prompt written as a user would type it, a deterministic scaffold script that generates its fixture into the case workspace from a seed, and its graders. Eight cases force a large read (a generated client over 32 KB with a three-line bug, a CI log over 20K lines with one stack trace near the end, a fixtures JSON over 256 KB, a 3K-line module with scattered callers, a flaky 2K-line suite, a 1,500-line reference loader to port, a renamed symbol across 40 files, a 900-line changelog to summarise). Three are controls under the threshold (a typo in a 60-line file, a test for a 200-line module, a question about a file of 25 KB) where a gate must never fire. Fixtures are generated, not committed, so nothing eval-shaped sits in a candidate's workspace, and no prompt, case name or scaffold path contains the blinding words of /eval § Blinding non-negotiables.

grade-read-shunt.py grades a run from transcripts, never from what the candidate said. Given a results directory it emits one row per run with: parent whole-file large reads; routing-around attempts (bare shell reads, Grep with -C of 50 or more or head_limit: 0 on a large file); hook decisions and repeated identical denied inputs when a shunt log is present beside the transcript; bytes delivered into the parent; the largest single result; the parent's final context size; compaction count; sub-agent tokens and tool uses; wall time from the first to the last timestamp; re-read rate (a parent read of a path that an earlier Agent prompt or sub-agent result named); and the outcome grade the runner recorded. It then prints per-task means per arm as paired rows, so two runs of the suite (control plugin, candidate plugin) compare task by task. Both scripts import read_transcript.py, the one place that knows the JSONL shape; a Read, Bash, Agent or usage block that shape cannot read ends the run with exit 2 and the offending line, never a silent zero.

The judge rubric is written into the suite before any run: patch correctness against the reference, diff minimality, whether the parent re-derived what a reader had returned, and whether the answer makes claims nothing that reached the parent supports. /eval § Mode C — behavioural lift with cost documents the two scripts, the metrics and the thresholds from specs/read-shunt.md.

Inputs

  • Session transcripts: <root>/<project>/<session>.jsonl and <root>/<project>/<session>/subagents/agent-<id>.jsonl, one JSON object per line, with tool_use blocks in message.content, toolUseResult beside each tool_result, message.usage on assistant lines, isSidechain and agentId markers.
  • Thresholds --bytes, --lines; --json; --paths; --root.
  • An eval results directory from claude plugin eval --json or from the Workflow-based /eval Mode B, plus the transcripts those runs left.
  • A shunt decision log, when a later build adds the hook.

Outputs

  • The incidence report on stdout, Markdown or JSON, and the committed baseline under tasks/eval-results/read-shunt/.
  • One grader row per run and paired per-task means per arm, Markdown or JSON.
  • The eval suite directory and its rubric.
  • A closed PR #128 with its evidence preserved in this tree.

Edge Cases

  • A transcript line that is not valid JSON is skipped and counted under malformed; a transcript with no tool use at all yields a zero row, not an error.
  • A root with no transcripts, or a transcript whose Read block the parser cannot read, exits 2 with the path.
  • Windows paths with backslashes and drive letters are compared after normalisation, so a re-read is detected whichever spelling the model used.
  • A Read of an image, PDF or notebook has a different toolUseResult shape and is excluded, not misclassified as a zero-byte text read.
  • A Bash command with cat inside a pipeline, a subshell or a heredoc is not a bare read; sed -n '1,$p' f is.
  • Sub-agent reads never raise the parent's count, including reads a forked sub-agent makes with the parent's context.
  • The grader reads a results directory with one arm as readily as two; with one arm it prints rows and no paired means.
  • A scaffold that produces a fixture under the size its case promises fails the suite's own test, before any paid run.
