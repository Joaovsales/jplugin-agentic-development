¶ Summary

A slice that opts in with a > Candidates: <N> line is built N times, each Builder in its own detached worktree. candidates.py rank measures and verifies every candidate itself, ranks them by a fixed lexicographic key, applies the winner's diff to the main tree, records every candidate with the reason for its place in the run ledger, and removes every candidate worktree — also when it is cancelled. The decision not to miss: eligibility is the three-outcome slice_result (#441), so a candidate whose check failed or did not run sorts behind every eligible one and is never applied.

Behavior

  1. /build reaches a slice whose heading in tasks/todo.md carries > Candidates: <N> (N ≥ 2). Without that line the slice builds as before.
  2. candidates.py open --slice <n> --count <N> creates N detached worktrees at the current HEAD through bootstrap-worktree.sh --detach-head (the worktree setup /build and /eval already use), at <toplevel>/../<repo>-slice-<n>-c<k>, and prints one candidates: c<k> <path> line each. It is all-or-nothing: a failure removes the worktrees it already made.
  3. /build dispatches one Builder per path with the slice's normal delegation prompt and the rule "edit only inside <path>".
  4. candidates.py rank takes each dispatch's claim (--agent c<k>=true|false|unknown, absent = unknown) and the affected-test command after --. For each candidate in id order it stages the worktree, measures the diff against the worktree's starting commit, then runs the verification through slice_outcome.py inside that worktree.
  5. It ranks, prints one line per candidate, records them in the run ledger, applies the winner's diff to the current tree with git apply, and removes every candidate worktree.
  6. Slice Close then runs as for any slice, against the applied winner.
  7. candidates.py discard --slice <n> removes the slice's candidate worktrees when the build stops between open and rank.

Inputs

  • open --slice <n> --count <N>: slice number, N ≥ 2.
  • rank --spec <spec> --slice <n> --branch <b> --base <sha> [--run-id <id>] [--ledger <dir>] [--agent c<k>=<v>]... -- <verification command>: the slice's Surface comes from the spec through slice.py's own resolver; branch and base are the build's, as Phase 6 passes them.
  • discard --slice <n>.

Outputs

rank prints, in rank order:

candidates: c<k> rank=<r> selected|discarded eligible|ineligible checks=<p>/2 diff_lines=<d> outside_surface=<o> <LABEL> — <reason>
candidates: applied c<k>
  • Reasons: the winner selected: ahead of c<j> on <signal> (<a> vs <b>), or selected: only eligible candidate; an eligible loser behind c<j> on <signal> (<a> vs <b>), where c<j> is the candidate ranked just above it; an ineligible candidate ineligible: <LABEL>.
  • The run record (tasks/runs/<run-id>.json) gains candidates: {"<slice>": [ {candidate, rank, selected, eligible, agent_result, verification_result, slice_result, label, checks_passed, diff_lines, outside_surface, reason} ]}. The schema stays run-ledger/1: the field is additive, record keeps it, stats does not read it.
  • Exit: 0 a winner was applied; 1 no eligible candidate (nothing applied), the winner's diff does not apply (the patch is kept under tasks/tmp/), or no candidate worktree exists; 2 usage.

Ranking key

Lexicographic and total, smallest first:

  1. eligible before ineligible (eligible ⇔ slice_result=True SUCCEEDED);
  2. more checks passed (agent_result and verification_result that are True);
  3. fewer diff lines (added plus deleted, a binary file counts 1);
  4. fewer changed paths outside the slice's Surface;
  5. lower candidate number — the tiebreak that makes the order total.

Nothing outside these recorded measurements — model confidence, timing, dispatch order — enters the key.

Edge Cases

  • A Builder commits inside its worktree: the diff is measured against the commit the worktree started at (stored in the worktree's git dir), so committed and uncommitted work both count.
  • Verification creates files (caches, logs): the diff is measured and the patch captured before verification runs.
  • No candidate is eligible: every candidate is recorded discarded, nothing is applied, exit 1 — the slice goes to Step 3 like any failed slice.
  • An empty diff that passes its checks is eligible and ranks first by size; Slice Close's surface check then reports every Surface path untouched.
  • rank is cancelled (SIGTERM, SIGHUP, Ctrl-C): a finally removes every candidate worktree before the process exits non-zero.
  • open when the slice already has candidate worktrees: refused, naming discard.
  • The main tree moved since open (another slice landed): the winner's diff is applied with git apply; a conflict exits 1 and keeps the patch.

Interfaces

  • Path: .agents/skills/build/scripts/candidates.py
  • Hides: where candidate worktrees live, each one's base commit, how a diff is measured, the ranking key and the cleanup on cancellation.
  • Interface: candidates.py open|rank|discard --slice <n> …
  • Alternative considered: a pure rank over measurements the orchestrator gathers — it lost because the orchestrator would then measure and verify by hand, and an agent-quoted result is the input #441 removed.
  • Depth: one rank call verifies, measures, ranks, records, applies and cleans up N worktrees.

Acceptance Criteria

  1. ✓CriterionAC1

    the same candidate set always gives the same ranking — rank over the same measurements in any input order prints the same lines, and two rank runs over identically built worktrees print identical candidate lines.

    covered by slice 1

  2. ✓CriterionAC2

    a candidate that failed any check — verification_result or agent_result not True — is never selected or applied, even when its diff is the smallest; with no eligible candidate rank exits 1 and the main tree is unchanged.

    covered by slice 1

  3. ✓CriterionAC3

    every candidate worktree is removed after rank — on success, on no winner, and when rank is terminated mid-verification — and discard removes them when the build stops before rank.

    covered by slice 1

  4. ✓CriterionAC4

    the run ledger record holds one entry per candidate with its rank, selected flag, three outcomes, measurements and the reason for its place.

    covered by slice 1

  5. ✓CriterionAC5

    /build names the opt-in line, the open → dispatch → rank flow and discard; .agents/skills/build/references/candidates.md and references/run-ledger.md document the commands and the candidates field.

    covered by slice 2
