Illegal states

  • task depends on itself — CLI refusal, pre-configuration
  • dependency that no row names, written through this flag — upsert_task refusal before any provider call. Not unrepresentable in general: a hand-typed row can name anything, and a predecessor re-filed under a new title mints a new id and leaves the old row standing (D7)
  • the same id twice — dict.fromkeys at the CLI
  • flag value silently overwritten by the record on disk — owned removes depends_on from the carried set for that run
  • existing blocker silently dropped by the flag — the <old> → <new> disclosure on preview and applied lines

Transitions — depends_on across runs. depends_on is not a status and never changes Task.status; [!] blocked stays human-set (specs/task-registry.md AC-7).

Open — needs the reviewer:

  • D2: refuse a dependency that names no existing row, or accept it and report it? Refusal protects the future consumer from a task it would skip forever and keeps preview equal to apply, at the price of filing slices one after another. Acceptance lets a filer record a blocker before the blocker is filed. The recommendation is refusal, because the rendered document — this page — is where all slices are reviewed at once.
