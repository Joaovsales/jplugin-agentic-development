¶ Summary

A Claude Code mod (a plugin of function hooks) that shows how a jplugin session is going, in one docked pane: the workflow phase and the running skill, slice progress read from tasks/todo.md, the sub-agent tree with each agent's brief and footprint, and the quality gates — findings, the quality receipt, ambiguities, surface reports and dispatch checks. It observes and never intervenes. It is a standalone mod at mods/session-viz/, beside mods/factory-board/, whose Kanban it supersedes.

Behavior

The pane session-viz, titled Session, opens at session.start where the surface docks panes and on /session-viz (focused). Its body is one column of stacked sections, in this order:

  1. Phase — the phase (PLAN, BUILD, GATE, WRAP-UP, or idle), the skill running now, and the /go route (lane, chain) when one was printed.
  2. Plan — the active ## Plan: block of tasks/todo.md: feature, spec, slice k/N closed (a slice is closed once its > Handover: blockquote exists), rows done over rows total, and one line per slice (n/N name · rows d/t · ✓ handover).
  3. Agents — every sub-agent of the session as a tree indented by parent, in spawn order, one Button row each: a glyph (◐ running, ✓ answered, ✗ failed or killed, ⚑ an open AskUserQuestion or [AMBIGUITY] lines in its answer), the factory stage (plan, build, review from the agent type's name, as factory-board derives it), the type, the description, and its status or duration.
  4. Gates — the quality receipt (verdict fp8 · tests exit N · unresolved N, or no receipt yet), the last Verdict: line seen, finding counts by severity, every [AMBIGUITY] line with its agent, every [SURFACE] +path report, and the dispatch issues (off-tier and missing-contract-item) the toasts announced.
  5. Drill-down — the pressed agent's brief and footprint: description, type, requested and resolved model, parent model and parent agent, the spawn prompt (first 2000 characters, then … +n chars), files read, files edited, patterns grepped, commands run, tool-call count, step count, message count, outcome and duration, [AMBIGUITY] and [SURFACE] lines, finding counts. Pressing the row again closes it. Pressing also scrolls the transcript to the Agent tool row that spawned the agent. No transcript is read or shown.

From 120 body columns the drill-down is a right column beside sections 1–4; below that it is the last section. Every section shows one dim line when it has nothing.

The status line reads viz · <PHASE> · <skill> · slice k/N · ctx NN% · $X.XX · agents R/T with every unknown field left out.

Three toasts, and no others:

  • session-viz: quality gate STOP (<fp8>) — a receipt whose verdict is STOP, once per fingerprint, or a main-loop answer line Receipt: STOP … or Verdict: … STOP, once per turn. HOLD never toasts.
  • session-viz: <type> dispatched on <model> (<tier>); model-routing says <tier | inherit> — an agent.spawn whose model tier disagrees with .agents/references/model-routing.md (D11).
  • session-viz: <type> dispatch missing contract item(s) <n, …> — a reviewer spawn whose prompt lacks the marker of any of the seven items of .agents/references/review-dispatch-contract.md (D10).

Observe-only: every hook passes e to next unchanged and returns what next resolved; no hook returns deny, rewrites a field, or answers for the engine. The pane, the status line and the toasts are the only outputs.

Engine calls: $.agent.list() (ids, types, descriptions, parents, statuses), $.fs.read and $.fs.stat (tasks/todo.md, .git, the receipt files), $.session.repo() (the main working tree's root), $.ui.open, $.ui.status, $.ui.toast, $.ui.scroll, $.ui.resolve(e), $.command.register, $.clock.every, and $.state through atom, read and update from 'claude-code'.

Files and text conventions parsed:

  • tasks/todo.md — ## Plan: <feature>, > Spec: specs/<x>.md, ### Slice n/N — <name>, - [ ]/- [x] header rows, indented [ ] TDD:, [x] TDD: and [ ] Verify: rows, > Handover: blockquotes. \r is stripped first.
  • [ROUTE] lane=<lane> | chain=<skill, …> | reason: …
  • [AMBIGUITY] <text> | options: … | picked: <letter> | reason: …
  • [SURFACE] +<path> | reason: <sentence>
  • [MUST-FIX | confidence: N | autofix_class: … | owner: …], with an optional <n>. prefix, as .agents/references/finding-model.md § Emission format spells it; severities MUST-FIX, SHOULD-FIX, NITPICK.
  • Receipt: <GO|HOLD|STOP> <fp8> … and Verdict: <glyph>? <GO|HOLD|STOP> lines.
  • The quality receipt: <repo root>/.git/quality-receipts/branch-<branch>.json ({ fingerprint }) then <fingerprint>.json (schema, verdict, tests.exit, unresolved[], design_verdict), <branch> sanitized as receipt.py does ([^A-Za-z0-9_.-] → -). The branch comes from .git/HEAD (a file .git in a worktree is gitdir: <path>; HEAD is read there).

Outputs

  • The pane session-viz and its tree, validating on the terminal and desktop surfaces.
  • One status line entry, replaced on every change.
  • The three toasts above, and nothing on HOLD, GO, a finished agent or an [AMBIGUITY] line.
  • Session state under $.state for the plugin session-viz: phase, agents, asking, selected, plan, gates, measure, toasted — declared in types/index.d.ts (§ Implementation Paths), nothing in $.store.
  • $.ui.scroll({ to: { requestId: <toolUseId> } }) on a row press.

Edge Cases

  • Hot reload. register runs again and module variables start over: every value a drawing or a toast decision reads is in $.state, the set of fingerprints and turns already toasted included, so a reload neither empties the pane nor repeats a toast.
  • An agent the hooks never saw (spawned before the mod loaded): the sync adds it from $.agent.list() with no toolUseId, the prompt (spawned before session-viz loaded) and an empty footprint; its press opens the drill-down without scrolling.
  • An agent whose parent is unknown is drawn as a root.
  • e.skill with a plugin prefix (jplugin:build): the phase map matches the segment after the last :.
  • [ROUTE] printed mid-turn: it is read off every main-loop turn.step result, not only the turn's final answer.
  • No recorded spec: the Plan section shows the last ## Plan: block holding an open [ ] row, else the last block, else no plan block.
  • tasks/todo.md missing or unparseable: the Plan section reads no plan block; nothing is logged to the model and no hook fails.
  • Detached HEAD, no .git, or a receipt file missing or malformed: the Gates section reads no receipt yet or receipt unreadable; no toast.
  • No surface (claude -p, a desktop session before a page attaches): $.ui.open resolves isPlaced: false and the pane waits; the status line and the toasts are still set and do no harm.
  • Narrow pane: below 120 body columns the drill-down is the last section; every row is truncated to the body width with ….
  • Caps: 200 agents (the oldest finished rows leave first), 40 entries per footprint list (the drill-down says +n more), 2000 characters of spawn prompt drawn, 50 ambiguity and 50 surface lines kept.
  • Tool names differ per build (a native build registers no Glob or Grep): the footprint compares String(e.tool) and reads the fields by name.
  • The turn.step hook is an async generator (async function* ($, e, next) { const result = yield* next(e); …; return result }); a plain function there is a type error and loads nothing.
  • The CLI on PATH may be older than the engine that runs the session (2.1.277 here, against a 2.1.299 engine): claude plugin validate there refuses the update($, …) helper and has no plugin test. The build checks claude --version is 2.1.299 or later before the first validate and upgrades it when it is not (D15).
  • Load: one person, one session, at most a few hundred agents and a tasks/todo.md of a few thousand lines; every parse is linear and runs on a change, never on a timer.
