¶ Summary

gate-integrity.py compares every protected file — test runners, the expected-failures list, CI workflows, lint and test configs — against its blob at a base commit by content hash, never by reading a diff. /build runs it at Slice Close, where a protected change outside the slice's Surface stops the slice as GATE_TAMPERED, and /quality-gate runs it as Phase 0, where it becomes a MUST-FIX. Added expected-failure rows, new skip markers and deleted assertions are always reported, and a check that cannot run says not checked.

Behavior

python3 .agents/skills/quality-gate/scripts/gate-integrity.py --base <rev> [--spec <spec> [--slice <n>]] [--repo <dir>] checks the working tree of <repo> (default: the current directory) against <rev>:

  1. Protected set. The protected patterns are the default list below, every glob on a Protected paths: line below the AGENTS.md end marker (whitespace-separated, backticks stripped, several lines allowed), and the file named on the Expected failures: line. Defaults: .github/workflows/**, .gitlab-ci.yml, .circleci/**, .pre-commit-config.yaml, .eslintrc*, eslint.config.*, .prettierrc*, pyproject.toml, setup.cfg, tox.ini, pytest.ini, .flake8, ruff.toml, .ruff.toml, mypy.ini, .golangci.yml, .golangci.yaml, jest.config.*, vitest.config.*. The candidate paths are the files in the base tree (git ls-tree -r) and the tracked and untracked, non-ignored files of the working tree (git ls-files -c -o --exclude-standard); a candidate is protected when a protected pattern matches it.
  2. Content comparison. Each protected path's base blob id (from ls-tree) is compared with git hash-object of the working-tree file. An added, deleted or edited file differs. Because the working-tree bytes are hashed and the base blob is read from the object store, an assume-unchanged or skip-worktree bit, a change already committed after the base, and a diff.mnemonicPrefix or diff.noprefix setting all leave the result unchanged.
  3. Surface. With --spec and --slice, the Surface is that slice's § Build Order Surface (the implicit one-slice plan reads implementation_paths); with --spec alone it is the union of every slice's Surface; with neither it is empty. A Surface entry declares a protected path when it matches the path and the entry itself lies wholly inside a protected pattern — tests/expected-failures.txt and .github/workflows/** declare, a broad tests/** does not.
  4. Report. One line per result, then one summary line:
LineWhen
GATE_TAMPERED <path> — changed since <base8>, not declared in the surfacea protected path differs and no Surface entry declares it
GATE_CHANGED <path> — changed since <base8>, declared in the surfacea protected path differs and a Surface entry declares it
EXPECTED_FAILURE_ADDED <path> — <row>a non-comment, non-blank row of the expected-failures file is new since the base — always, declared or not; the row names the test file and the failing assertion
SKIP_ADDED <path>:<line> — <text>an added line of a test file that existed at the base carries a skip marker
ASSERTION_DELETED <path>:<base line> — <text>a line carrying an assertion was removed from such a test file and is not re-added anywhere in it
NOT_CHECKED <path> — <reason>one file could not be read or hashed

Summary: gate-integrity: GATE_TAMPERED (<n>), gate-integrity: findings (<n>), gate-integrity: clean, or gate-integrity: not checked — <reason>.

  1. Exit status. 1 when any GATE_TAMPERED line printed; otherwise 3 when the check could not run or any NOT_CHECKED line printed; otherwise 0, with or without findings. 2 is bad usage (argparse, an unreadable spec or an unknown slice).

Skip markers are .skip, .only, @skip/@pytest.mark.skip/skipif/xfail, unittest.skip, pytest.skip(/pytest.xfail(, @Disabled, @Ignore, #[ignore], xit(/xdescribe(/xtest(/fit(/fdescribe(, t.Skip(, and a line starting with skip (this repository's tests/lib.sh). Assertions are lines carrying assert…, expect(, t.Error/t.Fatal, require. or should. A test file has a test, tests, spec or __tests__ directory segment, or a name test_*, test-*, *_test.*, *.test.*, *.spec.* or *Test.*.

In the skills

  • /build § Slice Close runs the script with --base <sha> --spec <spec> --slice <n> next to slice.py check. Exit 1 stops the slice: the header stays [ ], the handover records unfinished: GATE_TAMPERED <paths>, and the slice stays out of the done set, so nothing blocked by it becomes ready. Exit 3 is recorded as gate integrity: not checked — <reason> in the handover's > Surface: line, never as clean. Every finding line goes on that line too.
  • /quality-gate Phase 0 — Gate Integrity runs the script with the merge-base from Scope and the spec when one exists, before Phase 1. GATE_TAMPERED is [MUST-FIX | confidence: 100 | autofix_class: manual | owner: human]; every other result line is [SHOULD-FIX | confidence: 75 | autofix_class: manual | owner: human]. All go to Reported, not applied and the receipt's unresolved; exit 3 is named in Not checked:.

Inputs

  • --base <rev>: any revision git rev-parse resolves.
  • --spec, --slice: a spec with implementation_paths frontmatter and an optional § Build Order.
  • AGENTS.md below <!-- jplugin-agentic-development:end -->: Protected paths: and Expected failures: lines. No AGENTS.md means the defaults alone.

Outputs

Result lines and a summary on stdout, NOT_CHECKED reasons included; the exit status above. The script writes nothing.

Edge Cases

  • assume-unchanged hides an edit from git diff and git status: still GATE_TAMPERED.
  • An edit committed after the base, with a clean working tree: still GATE_TAMPERED.
  • diff.mnemonicPrefix=true or diff.noprefix=true: results are identical.
  • A protected file deleted, or a new file under a protected glob: GATE_TAMPERED.
  • The base does not resolve, or the directory is not a git work tree: gate-integrity: not checked — <reason>, exit 3.
  • An invalid glob on a Protected paths: line: not checked, exit 3, naming the glob.
  • A test file deleted outright: one ASSERTION_DELETED line per assertion it held.
  • An assertion moved within its file (removed and re-added identically): no finding.
  • An expected-failures row only reordered: no EXPECTED_FAILURE_ADDED line.
  • A row added to the expected-failures file inside a declared Surface: GATE_CHANGED plus EXPECTED_FAILURE_ADDED.

Interfaces

gate-integrity.py

  • Path: .agents/skills/quality-gate/scripts/gate-integrity.py
  • Hides: the protected-set resolution (defaults, AGENTS.md declarations), blob-vs-hash comparison, the surface-declaration rule and the skip/assertion patterns.
  • Interface: gate-integrity.py --base <rev> [--spec <spec> [--slice <n>]] [--repo <dir>] → result lines, exit 0/1/3.
  • Alternative considered: a slice.py check --gate flag. slice.py is already 865 lines and /quality-gate has no slice; one script both callers share keeps the rules in one place.
  • Depth: one call resolves the protected set, hashes every candidate, reads the surface and classifies every change.
