¶ Summary

Every /build session, and every rework run after review, writes one JSON record to tasks/runs/<run-id>.json: the spec, the base SHA, the model per tier, each slice's attempts and three outcomes, tokens and cost, the parent run it reworks, and the human result of its pull request. run_ledger.py stats recalculates first-pass rate, attempts per merged PR and cost per merged PR from those files alone. The decision not to miss: the human result has its own command, decide, and record has no option that sets it, so no later run can overwrite a human's merge or close.

Problem

A build or routine run leaves a PR and a handover, but nothing durable links its attempts, models, cost and the human outcome, so first-pass rate and cost per accepted PR cannot be calculated. This change adds the per-run record and the report over it. Out of scope: reading PR state from GitHub automatically (the human result is recorded by whoever observes it), and Helix's run.json (specs/helix-checkpoint-loop.md:262, not built).

⊞Data model

Derived totals

A PR is a chain of runs linked by parent_run_id, rooted at the run with no parent (or whose parent is not in the ledger). A chain is merged when any run in it is merged, otherwise closed when any is closed, otherwise open. First pass is a merged chain of one run whose decisions are exactly ["merged"]; the rate's denominator is the merged plus closed chains. Attempts are the runs in a chain. Cost and tokens per merged PR sum every run in the merged chains and divide by their count; one unknown run makes its chain unknown, and any unknown chain makes the aggregate unknown with the count. A parent cycle exits 1 naming the runs.

⊞Data model

Migration and compatibility

No existing data. Records written before a future run-ledger/2 are read by a /1 reader only; stats refuses an unknown schema rather than guessing.

Where records live
