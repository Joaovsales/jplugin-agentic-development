Problem — what changes, for whom

Every Claude Code session in this repository loads about 15k tokens of instructions from four files — CLAUDE.md (493 lines, 29 KB, 54 % review-protocol text), a stale ~/.claude/CLAUDE.md copy, .claude/project.md, and a session banner that restates the skills table a third time — while Pi and Codex each read a different subset. After this change every harness reads one AGENTS.md: template rules inside a marker-delimited managed block under 200 lines, project rules below it, CLAUDE.md reduced to @AGENTS.md, protocol detail in .agents/references/, and the Claude Code hooks shipped by the jplugin plugin. Out of scope, filed as follow-ups after approval: auto-running the block write on a project's first session (Q12), a repository-qualification guard for auto-sync (Q13), a graphify PreToolUse warning (Q23); also feat/106 re-baselining and any skill-body change beyond repointing citations.

Component contracts — can the caller ignore a case it must handle

Managed block (markdown, both directions of /sync)

<!-- jplugin-agentic-development:begin -->
## <heading>            # `## ` and `### ` only — the project's `# ` title stays the sole H1
…
<!-- jplugin-agentic-development:end -->
  • Source: the template repository's own AGENTS.md; the block is whatever lies between its markers
  • Invariants: ≤ 200 lines; no line starts with @; no match of the registry's POINTER_RE (case-insensitive, mid-line — config.py:36), so the convention is documented with <path>, never an example path; no # heading; namespace sentence present; the [AMBIGUITY] … | options … | picked … | reason format line and the TODO(shortcut): marker present verbatim (D21); fixed heading set in order
  • Legacy: coding-agent-workflow markers (render-codex.py:23-24) recognised on read, replaced on write
  • Versioning: none — replaced wholesale; the template's git history is the version

sync-managed-block.py (.agents/skills/sync/scripts/)

python3 sync-managed-block.py --source <template-AGENTS.md | -> --target AGENTS.md \
    [--claude-md CLAUDE.md] [--migrate .claude/project.md] [--dry-run]
  • Outcomes (one stdout line each): AGENTS.md: replaced · appended · unchanged · CLAUDE.md: written · unchanged · migration: moved <n> section(s), .claude/project.md deleted · migration: nothing to move
  • Exit 2, before any write: source lacks a marker pair; target has an unmatched marker or > 1 begin; --migrate finds ## Deployment Targets in both places; --claude-md target is a directory
  • Raises: I/O errors only, with the path
  • Idempotency: re-run is a no-op reporting unchanged; --dry-run prints would … and writes nothing
  • Writes: tempfile + os.replace per file; outside-marker bytes copied verbatim incl. line endings. Fixed order — AGENTS.md first, then CLAUDE.md, then the project.md delete last — so a crash duplicates and never loses
  • Migration (--migrate): moves everything in project.md below its header except ### Code Economy, ### Surgical Changes, ### Ambiguity Protocol, ### Large-Artifact Handoff and the ### Task Tracking placement prose (the block owns all five); pointer line first, then the rest in original order with headings unchanged, appended below the end marker; an existing ## Project-Specific Rules heading is reused (D15)

Illegal states

  • two managed blocks in one AGENTS.md — script refuses on begin-count ≠ 1; budget test
  • CLAUDE.md with content beyond the import — budget test byte-compare; /sync rewrites it
  • a live pointer inside the block — budget test with POINTER_RE
  • a ## Deployment Targets table in two places — --migrate exit 2; readers take AGENTS.md first and print the notice
  • a rule with two homes — citation test + review; the block names a standard in one line and cites the skill
  • a hook registered in the plugin and in .claude/settings.json — template file asserted clean; downstream entries dropped by the same /sync that retires the scripts (only session-start.sh has a session_id guard)
  • a settings.json entry pointing at a retired script — removal and retirement are one step; a hand-kept entry surfaces in the drift line
  • a reviewer dispatched without the output format — dispatching skills refuse after the three-location lookup
