03

From intent to dispatch

Four synchronous boundaries make routing inspectable before a child starts.

01 / Resolve

Skill or routine

Requests lane + role from versioned policy. Unknown input fails explicitly.

02 / Render

Policy adapter

Validates model and effort; emits deterministic native Codex TOML.

03 / Inspect

Preview & apply

Reads config layers, reports drift, backs up changed user-owned files.

04 / Spawn

Codex host

Uses the named role. Missing or unmanaged routes stay visible to doctor.

lane + role → resolve() → render() → inspect() → preview() → opt-in apply() → named child

Failure units stay local: validation and preview work outside a session; an ambiguous apply preserves personal config; one missing Scout route affects one investigation.

04

Contracts with teeth

Each boundary has a success shape and a refusal shape.

Contract A / pure

Resolve policy

resolve(policy, harness="codex", lane, role, parent_model) → Route | Unsupported | InvalidPolicy

A Route carries tier, model or explicit inheritance, effort, permission intent and supported limits. Unknown schema versions refuse rather than reinterpret.

Contract B / read-only

Render & inspect

render(policy, agents) → DesiredCodexFiles
inspect(desired, context) → Match | Missing | ManagedDrift | LegacyCandidate | PersonalConflict | InvalidInstalled | UnknownLayer

Explorer uses a read-only sandbox. The investigator retains MCP access for /why. A higher-priority unavailable layer produces UnknownLayer.

Contract C / mutation gate

Preview & apply

preview(desired, installed) → Plan
apply(plan, codex_home, explicit_opt_in) → Applied | Refused | Failed

Preview lists actions and backup paths. Apply refuses ambiguous conflicts, writes atomically, and is idempotent on retry.

08

Decisions in the open

Six recorded choices. Three are assumptions with explicit conditions that would change them.

Full #158 scope

Chosen over /how guidance alone. Guidance cannot fix inherited-model install behavior.

Scout = gpt-6-luna

User choice. If the account lacks access, live spawn must fail clearly; static doctor cannot prove entitlement.

Pin named Scout roles / assumed

Chosen over a global Luna default. Revisit only if Ceiling inheritance has explicit compatible resolution.

Include minimal #157 foundation / assumed

Leave Claude/Pi emitters to #159. Revisit if #157 is already being built separately.

Explicit routine mappings / assumed

Planner Astra/high; Builder and Reviewer Sol/medium. Revisit when a model is unavailable or mismatches tier purpose.

Exact-shape legacy adoption

Preview and opt-in instead of overwriting; decline if candidate detection cannot prove template origin.

09

Done means observable

The eight acceptance outcomes are written as inspection targets rather than decorative status badges.

  1. Versioned policy resolves every Codex lane and workflow role to tier, effective model and effort, permissions and supported limits; explain traces or refuses input.
  2. Deterministic emitter produces managed TOML for canonical roles plus read-only explorer/Scout on gpt-6-luna; routine roles do not inherit accidentally.
  3. Ceiling and floors resolve under actual precedence; no global setting silently turns high-stakes work into Scout.
  4. /how routes reconnaissance to managed explorer and synthesis to Ceiling; /why uses MCP-capable Scout. Model IDs stay in provider mapping.
  5. Other read-heavy skills select named Codex Scout roles; floor dispatch uses resolved parent tier; Claude/Pi routes stay intact.
  6. Concurrency has a conservative documented default or diagnosis when absent, plus an explicit override path.
  7. Install previews and backs up known legacy adoption, preserves personal and unrelated config, and repeats without changes.
  8. doctor --harness codex names expensive inheritance, missing caps and provenance or says unknown; conformance tests cover shadows, precedence, rendering, migration, drift and repeat install.
