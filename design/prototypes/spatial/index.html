Three contracts hold the route.

Each boundary has a specific result and failure behavior, so “installed” does not masquerade as “effective.”

01 / Resolve

Semantic intent → native route

resolve(policy, harness, lane, role, parent_model)

Pure and repeatable. Unknown roles, unsupported effort, or an unknown schema version return an explicit error before file access.

02 / Inspect

Desired files → actual precedence

inspect(desired, context)

Classifies managed drift, legacy candidates, personal conflict, invalid files, and unknown layers. Project shadows and CLI/cloud/session overrides remain visible as provenance limits.

03 / Apply

Preview → guarded change

apply(plan, codex_home, explicit_opt_in)

Names creates, updates, migrations, and backup paths. Ambiguous conflicts refuse apply; changed user-owned content is backed up; repeat installs make no new change.

Policy validation and preview can fail independently of a Codex session. A missing route affects one delegated investigation; the parent can still report the gap.

Acceptance checkpoints

  1. Versioned policy resolves every lane and role with a full trace.
  2. Managed TOML pins Scout and read-only explorer to Luna.
  3. Ceiling inheritance survives native precedence and floors.
  4. /how and /why select the right named roles without model IDs in prose.
  5. Other Scout skills use named roles; Claude/Pi routes remain intact.
  6. Concurrency has a conservative default or diagnosis and override.
  7. Migration preserves personal config, backs up changes, and is idempotent.
  8. Doctor names expensive inheritance, missing caps, and provenance limits.
