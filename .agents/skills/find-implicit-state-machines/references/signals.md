# Scan signals

What `scripts/state_machines.py scan` counts, and why each pattern suggests state.
The regular expressions live in the script's `SIGNALS` table; this file explains
them and is the by-hand fallback when Python is unavailable (`grep -nE` each
pattern, then rank files by the weighted sum).

A file ranks only when it shows **two or more signal kinds** — one `await` or one
`status =` is noise. Score = Σ weight × count. Comment-only lines are skipped:
prose about state is not state.

| Signal | Weight | Matches | Why it suggests a machine |
|---|---|---|---|
| `modal-switch` | 4 | `switch (x.status)`, `match self.mode`, `case "$state" in` | behavior chosen by state — the machine's dispatch table |
| `state-enum` | 4 | `enum OrderStatus`, `class Phase(Enum)`, `type Mode =` | named states exist; the transitions are usually elsewhere |
| `modal-assign` | 3 | `status = "paid"`, `this.phase: 'idle'`, `STATE=done` | a write to a modal variable is a transition |
| `modal-compare` | 3 | `status === 'pending'`, `mode == "x"`, `[ "$state" -eq 1 ]` | a guard on a modal variable |
| `transition-call` | 3 | `setStatus(`, `.dispatch(`, `.send(`, `transition_to(` | an explicit move, often called from many places |
| `flag-assign` | 2 | `isPaid = true`, `in_block = 1`, `OWNS_LOCK=1`, `build_done = False` | boolean flags read together form states |
| `flag-guard` | 2 | `if (!this.isReady`, `while not in_block`, `if [ "$OWNS_LOCK"` | a flag that gates which code may run |
| `toggle` | 2 | `infence = !infence` | a two-state parser machine |
| `marker-file` | 2 | `mkdir "$LOCK"`, `[ -f "$SENTINEL" ]`, `rm -f done.stamp`, `.exists()` on a lock | state kept on disk, shared across processes |
| `event-handler` | 1 | `addEventListener(`, `.on('x'`, `onClick=`, `trap '...' INT` | a handler that may fire in any state |
| `async-order` | 1 | `await`, `.then(`, `Promise.all`, `asyncio.gather`, `setTimeout(` | ordering that may be the only thing keeping state consistent |

## What never ranks

`state_machines.py signals` prints the signal weights and the directory, marker and
suffix lists below, and `tests/test-find-implicit-state-machines.sh` fails when this
file drifts from them. The test-name patterns, code extensions and the numeric limits
(two signal kinds, 500-character lines, five header lines) are kept here by hand.

- Files `.gitignore` excludes (inside git).
- Third-party and tool directories, everywhere: `node_modules/`, `vendor/`,
  `third_party/`, `third-party/`, `bower_components/`, `Pods/`, `.venv/`, `venv/`,
  `__pycache__/`, `.git/`, `.jplugin/`.
- Build output (`dist/`, `build/`, `out/`, `target/`, `coverage/`, `.next/`,
  `.nuxt/`) — by name only outside git; inside git `.gitignore` decides, so a
  source directory named `build` still ranks.
- Generated files: `@generated`, `DO NOT EDIT`, `Code generated`, `auto-generated`
  or `autogenerated` in the first five lines; any line over 500 characters
  (minified); the suffixes `.min.js`, `.min.css`, `.bundle.js`, `.d.ts`, `.pb.go`,
  `_pb2.py`, `.g.dart`.
- Tests and fixtures: directories `test/`, `tests/`, `spec/`, `__tests__/`,
  `e2e/`, `fixtures/`, `__fixtures__/`, `testdata/`; names `test_*.py`, `*_test.*`,
  `*.test.*`, `*.spec.*`, `*Test.*`, `*Tests.*`, `*_spec.rb`. Tests are read in
  Phase 2 for coverage, not ranked as machines.
- Non-code files (Markdown, JSON, YAML). A machine described only in docs is a
  spec, not an implicit machine; a config file a parser turns into states is found
  through the parser.

## Blind spots

The scan is a reading order, not a verdict. It under-ranks state held in a
database column written from SQL, state split across services, and a machine whose
variable has an unusual name (`step`, `kind`, `cursor`). Follow every machine past
the files the scan ranked, and grep the variable's name across the whole scope.
